# ♿ Accessibility (A11y) Baseline Standard

> **Target Standard**: WCAG 2.2 Level AA · Principle Zero: Accessibility is a pre-condition for use.

---

## 1. Core Mandates

1. **Semantic HTML First**: Always prefer native elements (`<button>`, `<a>`, `<dialog>`, `<details>`, `<label>`). Never use `<div onClick=...>` or `<span onClick=...>`.
2. **Color Contrast (SC 1.4.3, 1.4.11)**:
   - Body & Normal Text: Minimum **4.5:1** contrast ratio against background.
   - Large Text (≥18px / 14px bold) & UI Elements: Minimum **3:1** contrast ratio.
   - Never convey state with color alone; use **Icon + Text + Color**.
3. **Keyboard & Focus Management (SC 2.1.1, 2.4.7)**:
   - 100% of interactive flows must be operable via Tab / Enter / Space / Arrow keys.
   - Visible focus ring (minimum 2px thickness with 3:1 contrast) on every interactive element.
   - Never suppress focus (`outline: none` without a high-contrast replacement is forbidden).
4. **Modals & Dialogs**:
   - Use native `<dialog>` with `showModal()` or trap focus inside custom modals.
   - Focus moves into modal on open and returns to triggering element upon close.
5. **Touch Targets (SC 2.5.8)**:
   - Minimum interactive hit area of **24×24 CSS pixels** (WCAG AA floor); **44×44 CSS pixels** recommended as the agency ergonomic standard.
6. **Forms & Labels**:
   - Every input must have a programmatically linked `<label>` via `id`/`htmlFor` or direct element wrapping.
   - Visible error messages with `aria-describedby` linkage.

---

## 2. Automated & Verification Checkpoints

- **Zero Axe-Core Violations**: All automated test suites and page builds must pass `axe-core` audits with zero critical or serious violations.
- **Screen Reader Parity**: Accessible names (`aria-label`, visible text) must accurately describe control actions without duplicating visible strings awkwardly.
